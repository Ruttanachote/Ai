# Design brief: ระบบสารสนเทศ มหาวิทยาลัยการกีฬาแห่งชาติ (TNSU) — สำหรับ Claude Design

> วางไฟล์นี้เป็นข้อความแรก แล้วแนบไฟล์ 02 (workflow ทั้งหมด), 03 (UX/หน้าจอ/KPI) และ 04 (เอกสารออกแบบฉบับเต็ม) เป็นบริบท
> ภาษา: ไทยเป็นหลัก (ศัพท์เทคนิคอังกฤษได้) · ทุกข้อเท็จจริงที่ติด 🟡 หรือ [ต้องตรวจสอบ] ยังไม่ยืนยัน ห้ามแสดงเป็นข้อมูลจริงบนหน้าจอ ให้ใช้ตัวอย่างที่ติดป้าย "[ตัวอย่าง]"

## 1. สิ่งที่ขอให้ออกแบบ
ออกแบบ UI/UX ระดับ production ของ **แพลตฟอร์มบริหารวงจรชีวิตนักศึกษาและนักกีฬา** ของมหาวิทยาลัยการกีฬาแห่งชาติ (มกช./TNSU) โดยใช้ **Design System "Modernist"** ของโปรเจกต์นี้ (Swiss-school modernism: กริดเคร่ง, Archivo ทุกที่, มุมเหลี่ยม, เส้นแบ่งหนัก, สีแดงเน้นสีเดียวบนพื้นเกือบขาว)

ลำดับงาน:
1. **R1 ระบบรับสมัคร** (ทำก่อน — release แรก): flow ผู้สมัครบนมือถือ, ผู้ปกครอง, เจ้าหน้าที่รับสมัคร, กรรมการสอบทักษะ (แท็บเล็ต), การเงิน, ผู้อนุมัติ, หน้าประกาศสาธารณะ
2. **แอปนักศึกษา (PWA + LINE LIFF)**: หน้าแรก, ตารางเรียน, ลงทะเบียน (ตะกร้า/waitlist/conflict), จ่ายค่าเทอม Thai QR, เกรด/สถานภาพ, degree audit, คำร้องออนไลน์, ลาแข่ง, บัตรนักศึกษาดิจิทัล, กล่องแจ้งเตือน
3. **Back-office เจ้าหน้าที่** (ทะเบียน การเงิน กยศ. หอพัก กิจการ) แบบ power user
4. **มุมโค้ช/นักวิทยาศาสตร์การกีฬา/แพทย์**, **มุมผู้ปกครอง (ผู้เยาว์ในโรงเรียนกีฬา)**, **dashboard ผู้บริหาร** (อธิการบดี / รองอธิการวิทยาเขต / คณบดี / หัวหน้าภาค)

## 2. บริบทองค์กร (ใช้ในการออกแบบ — ตัวเลขเป็นค่าประมาณ)
- 17 วิทยาเขต (แต่ละแห่งบริหารค่อนข้างอิสระ: รอบรับสมัคร ค่าธรรมเนียม ผู้ลงนาม ตั้งค่าแยก) + โรงเรียนกีฬา 13 แห่ง (นักเรียน ม.1–ม.6 ส่วนใหญ่ผู้เยาว์ พักประจำ)
- นักศึกษา ~12,300 (รองรับ 15,000), นักเรียนโรงเรียนกีฬา ~4,450, บุคลากร ~2,700, ใบสมัคร ~30,000/ปี, บัญชีผู้ปกครอง ~12,500
- คณะ: ศึกษาศาสตร์ (ครูพลศึกษา — มีฝึกสอน), ศิลปศาสตร์, วิทยาศาสตร์การกีฬาและสุขภาพ; มี ป.โท/เอก
- นำร่อง: วิทยาเขตชลบุรี + มหาสารคาม; โรงเรียนกีฬานำร่อง สุพรรณบุรี

## 3. Personas หลัก (รายละเอียดในไฟล์ 03 หัวข้อ 1)
ผู้สมัคร (มัธยมปลาย/นักกีฬาเยาวชน มือถือ สัญญาณอ่อน) · นักศึกษาปี 1 · นักศึกษานักกีฬาทีมชาติ · นักศึกษาครูพลศึกษาที่ฝึกสอน · นักศึกษา ป.โท/เอก · นักเรียนโรงเรียนกีฬา (ผู้เยาว์) + ผู้ปกครอง (รวมปู่ย่าตายาย/ผู้อุปการะ, บางคนไม่มีสมาร์ตโฟน) · อาจารย์ผู้สอน/ที่ปรึกษา · หัวหน้าภาค · คณบดี · รองอธิการวิทยาเขต · อธิการบดี · เจ้าหน้าที่ทะเบียน (ทำคำร้อง ~300 เรื่อง/สัปดาห์) · การเงิน · เจ้าหน้าที่ กยศ. · หอพัก/ครูหอพัก · โค้ช · นักวิทยาศาสตร์การกีฬา · แพทย์/พยาบาล/นักกายภาพ · ผู้ดูแลคุ้มครองเด็ก · ศิษย์เก่า · นายจ้าง · ผู้ดูแลระบบ · ผู้ตรวจสอบ
บทบาททั้งหมด 69 รหัส (ไฟล์ 02 ส่วนต้น)

## 4. หลักออกแบบที่บังคับ
- **Mobile-first** สำหรับผู้สมัคร/นักศึกษา/ผู้ปกครอง (PWA ทำงานเมื่อเน็ตอ่อน, มีหน้า "สำเร็จหรือไม่" หลังเน็ตหลุด); เดสก์ท็อปสำหรับเจ้าหน้าที่ (คีย์ลัด, bulk action, Excel import/export, คิวงาน); แท็บเล็ตออฟไลน์ได้สำหรับกรรมการสอบทักษะ
- **ภาษาไทย:** Archivo ไม่มีตัวไทย → คู่กับฟอนต์ไทย (เช่น IBM Plex Sans Thai) ให้น้ำหนัก/ขนาดใกล้กัน; line-height เนื้อความไทย ≥ 1.6; ห้าม letter-spacing ติดลบกับไทยตัวเล็ก; วันที่ **พ.ศ.** เสมอ; สองภาษาไทย/อังกฤษ
- **Accessibility:** WCAG 2.1 AA ขั้นต่ำ (เป้า 2.2 AA), พื้นที่กด ≥ 44 px, contrast 4.5:1, ไม่สื่อด้วยสีอย่างเดียว, ไม่ใช้คีย์ลัดตัวอักษรเดียว
- **ความเป็นส่วนตัว:** ข้อความ LINE/SMS มีแค่หัวข้อ+ลิงก์ ห้ามมีเกรด/สุขภาพ/วินัย; ผู้ปกครองเห็นข้อมูลผู้เยาว์ แต่นักศึกษาอายุ ≥ 20 ต้องยินยอมก่อน; โค้ชเห็นสถานะนักกีฬา "พร้อม/จำกัด/ไม่พร้อม" เสมอ แต่รายละเอียดการรักษาต้องได้ consent
- **การแจ้งเตือน:** LINE OA บัญชีกลาง (LINE Notify เลิกแล้ว), push, อีเมล, SMS เฉพาะเร่งด่วน; มีระดับความสำคัญ, quiet hours, ส่งครั้งเดียวไม่ซ้ำช่องทาง
- **Multi-campus:** ทุกหน้าจอของเจ้าหน้าที่ต้องเห็นชัดว่ากำลังทำงานในวิทยาเขตไหน; ผู้ใช้หลายบทบาทมี role switcher
- **Exception-first dashboards** ผู้บริหาร (KPI-01..47 ในไฟล์ 03 หัวข้อ 12)

## 5. R1 ระบบรับสมัคร (ทำเป็นอันดับแรก)
ช่องทาง:
1. **โควตาเรียนดี**
2. **โควตานักกีฬา** — ระดับผลงาน (จังหวัด/เขต/ชาติ/นานาชาติ), ยืนยันเกียรติบัตร, สอบทักษะรายชนิดกีฬา + ทดสอบสมรรถภาพ, ให้คะแนนหลายกรรมการ (ค่าเริ่มต้น 3 คน/สถานี) + moderation, คัดกรองสุขภาพก่อนสอบ, ผู้ปกครองยินยอมถ้าอายุ < 20
3. **ประเภททั่วไป รอบ 1..N** (แต่ละวิทยาเขตตั้งรอบเอง ได้ถึง 5–6 รอบ ก.พ.–มิ.ย.)
4. **โควตาภายในจากโรงเรียนกีฬา** (ดึงผลการเรียน/ผลงานให้อัตโนมัติ)
5. TCAS (ทางเลือก ปิดเป็นค่าเริ่มต้น)

กติกาสำคัญ: บัญชีผู้สมัครเดียวทั้ง มกช. (ThaID หรืออีเมล+OTP), สมัครได้หลายวิทยาเขต แต่**ยืนยันสิทธิ์ได้ 1 ที่ต่อคนต่อรอบ** (ระบบตรวจตอนกดยืนยัน), คืนที่นั่งภายใน 15 นาที, อุทธรณ์ผลคัดเลือกต้องจบก่อนหมดเวลายืนยันสิทธิ์, ชำระด้วย Thai QR (บันทึกรูป QR ได้ เพราะมักใช้มือถือเครื่องเดียวกับแอปธนาคาร), ใบเสร็จอิเล็กทรอนิกส์, ผู้สมัครรอบท้ายได้ fast-track

หน้าจอขั้นต่ำของ R1:
- ผู้สมัคร (มือถือ): หน้าแรก/รอบที่เปิด → สมัครสมาชิก (ThaID) → เลือกวิทยาเขต-สาขา-ช่องทาง-ชนิดกีฬา → กรอกข้อมูล + ผู้ปกครอง → อัปโหลดเอกสาร (ปพ.1, เกียรติบัตร, ใบรับรองแพทย์) → ชำระเงิน → สถานะใบสมัคร (timeline) → บัตรประจำตัวผู้สอบ + วัน/สนามสอบ → ผลสอบ → ยืนยันสิทธิ์/สละสิทธิ์ → อุทธรณ์ → รายงานตัว
- ผู้ปกครอง: ลิงก์ยืนยันความยินยอม (หมดอายุ 72 ชม.), ช่องทางให้เจ้าหน้าที่ช่วยถ้าไม่มีสมาร์ตโฟน
- เจ้าหน้าที่รับสมัคร (เดสก์ท็อป): ตั้งค่ารอบ (ต้องอนุมัติ 2 คน), คิวตรวจเอกสาร, จัดตารางสอบ/จองสนาม, ประกาศผล, รายชื่อสำรอง/clearing, รายงาน
- กรรมการสอบทักษะ (แท็บเล็ต ออฟไลน์ได้): รายชื่อผู้สอบตามสถานี, rubric ให้คะแนน, ประกาศ conflict of interest, sync เมื่อมีเน็ต
- ประธาน/ผู้อนุมัติ: อนุมัติรอบ, moderation คะแนน, อนุมัติประกาศผล
- การเงิน: กระทบยอด callback ธนาคาร กับ statement, รายการผิดปกติ
- หน้าประกาศสาธารณะ: ประกาศรอบ เกณฑ์ ผลคัดเลือก (ไม่แสดงข้อมูลส่วนบุคคลเกินจำเป็น), หน้าเปิดเผยข้อมูล ITA/OIT
