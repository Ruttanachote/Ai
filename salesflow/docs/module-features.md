# One Platform — Feature ของแต่ละ Module (ตาม Requirement ฝั่งผู้ใช้)

อ้างอิง Requirement 4 ชุด: Solution Manager (SM-1…11), Project Manager (PM-1…8), Team Product (TP-1…10), Maintenance Support (MA-1…6)
สถานะเทียบกับต้นแบบปัจจุบัน: **มีแล้ว** = ใช้ได้ในต้นแบบ · **ปรับ** = มีบางส่วน ต้องเพิ่ม/แก้ · **ใหม่** = ยังไม่มี
ลำดับความสำคัญ: **P1** = ต้องมีก่อนใช้งานจริง · **P2** = ระยะถัดไป

## 2. Module Project Management (Project Manager)

|---|---|---|---|---|---|
| P1 | **รับมอบโครงการ** | PM เห็นโครงการที่ถูก Assign ใน “My Tasks” พร้อมสรุปจาก SM (ขอบเขต มูลค่า งวด เอกสาร) และนัด Handover | PM-1 | มีแล้ว | — |
| P2 | **ทีมโครงการตามบทบาท** | เพิ่มบทบาทในพื้นที่งาน: **SA, BA, UX/UI, Front-end, Back-end, DevOps, QA** (ตอนนี้มี PM/หัวหน้าทีม/Dev/QA/BA) · แต่ละคนมีหน้าที่สรุปไว้ในการ์ดสมาชิก (RACI) | PM-2, TP-2…6 | ปรับ | P1 |

| P5 | **Kick-off และนัดประชุม** | สร้างนัด Kick-off / ประชุมทีม / เข้าเก็บ Requirement เป็นนัดใน Outlook + Teams (เชิญจาก Stakeholder Register) และบันทึกประชุมลงเอกสารโครงการ | PM-3, PM-7 | ปรับ (มีบันทึกประชุม ยังไม่ส่งนัด) | P1 |
| P6 | **บริหารงวดงาน** | แต่ละงวด: % เงินตามสัญญา, จำนวนเงิน, กำหนดส่ง, **รายการส่งมอบ (Deliverables)** และงานที่ผูกกับงวด · ดูภาพรวมว่างวดไหนเหลืองานอะไร | PM-4 | ปรับ (เพิ่ม Deliverables ต่องวด) | P1 |
| P7 | **เลือกวิธีบริหารโครงการ** | Template: **Waterfall (ตามงวดงาน), Agile-Scrum, Kanban** พร้อมคำแนะนำว่าเหมาะกับโครงการแบบไหน · เปลี่ยนได้โดยงานเดิมไม่หาย | PM-5 | มีแล้ว (เปลี่ยนชื่อ “ตามงวดงาน” เป็น Waterfall) | P2 |

## 6. ลำดับการทำที่แนะนำ

1. **รอบที่ 1 (ตามใจผู้ใช้หลัก):** T3–T5 Timesheet/OT อัตโนมัติ, T7–T9 วันลา, M5 แจ้งเตือน 3/1 เดือน, M3–M4 รอบ PM
2. **รอบที่ 2 (คุมโครงการ):** P2–P4 ทีมตามบทบาท + Stakeholder, P6 + P10 งวดงานและเอกสารส่งมอบ, P8 Risk Register, T2 Weekly Report
3. **รอบที่ 3 (ฝั่งขาย):** S3–S6 เอกสารตามสถานะ + Requirement + TOR review + Proposal, S8 Reject ระบุจุด, S9 แจ้งวันประกาศผล, S11–S12 Win → แจ้งทีม/ให้สิทธิ์ PM
4. **รอบที่ 4:** S2 Solution Catalog, T6 My Performance, ปฏิทินกลาง

## 7. สิ่งที่ต้องยืนยัน
1. OT: เวลาหลัง 19:30 นับเป็น OT เสมอ หรือต้องครบ 8 ชม. ในวันนั้นก่อน
2. การลา: ใช้ระบบลาของ HR อยู่แล้วหรือไม่ (ถ้ามี ควรดึงข้อมูลมาแทนการลาซ้ำในระบบ)
3. รอบ Preventive Maintenance: ลูกค้าส่วนใหญ่กำหนดรายเดือนหรือรายไตรมาส และมี Template รายงานอยู่แล้วหรือไม่
4. แจ้งเตือนต่อประกัน: ส่งอีเมลจากกล่องกลางของทีม MA หรือจากชื่อผู้ดูแลแต่ละคน
5. ตรวจ TOR Final โดย “หัวหน้าทีม” คือหัวหน้ากลุ่ม DT ของ SM ใช่หรือไม่
